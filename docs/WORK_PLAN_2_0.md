# План работ 2.0

Версии с этого плана начинаются с 2.0.0, дальше 2.0.x. К релизу у расширения будет новое название.
Этап 1 собран как 2.0.0. Этапы 2–5 проверяются тестами без сборки; одна сборка 2.0.1 будет, когда готовы все пункты.

Порядок этапов: от простого к сложному. Этап 5 опирается на этап 2 (терминалы сабагентов).

## Этап 1. Индикатор контекста и изображения в чате (2.0.0)

- [x] **Пункт 7. Индикатор показывает полное окно.** Сейчас он показывает `maxInputTokens`, а это окно минус
  резерв под ответ (32 768 у Codex): 475k − 32k ≈ 443k. Индикатор и попап контекста показывают полное окно
  (`maxInputTokens + maxOutputTokens`), а в подсказке сказано, сколько зарезервировано под ответ.
  Порог сжатия не меняется.
- [x] **Пункт 2. Картинки, которые агент смотрел, открываются из чата.** Строка `🖼 имя · размер` у результата
  инструмента кликабельна (картинки пользователя и раньше открывались как вложения). Хост берёт данные картинки из сессии, пишет её
  во временный файл и открывает во встроенном просмотрщике VS Code.

## Этап 2. Терминалы без спама

- [x] **Пункт 1.** У каждой терминальной сессии есть владелец: основной чат или конкретный сабагент.
  - Свободный терминал своего владельца используется повторно.
  - Если свободного нет, а один завис (синхронная команда вышла по таймауту и давно не пишет вывод),
    зависший закрывается и только потом создаётся новый. Асинхронные команды (серверы, watch) не трогаем.
  - На владельца не больше 4 терминалов. Если все четыре заняты и ни один не завис, новый не создаётся,
    а модель получает список терминалов и совет прочитать, прервать или закрыть один из них.
  - У каждого сабагента свои терминалы с его именем. Когда сабагент закрыт, его свободные терминалы закрываются.

## Этап 3. Уведомления и продолжение после лимита

- [x] **Пункт 5. Системные уведомления ОС**, когда окно VS Code не в фокусе или свёрнуто: агент закончил,
  ждёт разрешения или задал вопрос. Windows: тост; macOS: `osascript`; Linux: `notify-send`. Уведомление
  внутри VS Code остаётся. Настройка позволяет выключить системные уведомления.
- [x] **Пункт 6. Автопродолжение после пятичасового лимита Codex и Claude.** На карточке лимита есть галочка
  «Продолжить автоматически после сброса», по умолчанию включённая.
  - Ко времени сброса (плюс минута) чат сам продолжает прерванный ответ, как по Retry.
  - Работает и для чатов в фоне и переживает перезагрузку окна.
  - Если пользователь снял галочку, сам отправил сообщение или нажал Retry, автопродолжения нет.
    Продолжает модель чата: если в чате выбрали другую, продолжит она.
  - После трёх продолжений подряд, снова упершихся в лимит, автопродолжение останавливается.
    Если продолжение пришлось на время, когда VS Code был закрыт, оно запускается после старта, если прошло меньше суток.

## Этап 4. Предел длины чата

- [x] **Пункт 3. В чате хранится не больше 1000 ходов** (ход = запрос пользователя вместе с ответом агента).
  - При открытии чата или запуске VS Code самые старые ходы сверх предела удаляются из истории и с диска.
  - Удаления по времени нет: короткий старый чат остаётся как есть.
  - То, что видит модель, по-прежнему ограничивает сжатие по токенам.

## Этап 5. Интерактивные сабагенты

- [x] **Пункт 4.** Сабагента можно запустить открытым (`keepOpen`), продолжить (`subagentId`) и закрыть (`close_subagent`).
  - После отчёта он остаётся открытым со своим контекстом. Модель проверяет работу и либо закрывает
    его, либо отправляет тому же сабагенту следующую задачу. Так можно повторять сколько угодно.
  - Открытые сабагенты сохраняются вместе с чатом и переживают перезагрузку.
  - Внизу чата есть панель активных сабагентов: что делает каждый, его модель и статус. Сабагента можно закрыть
    вручную, поэтому незавершённый сабагент не потеряется.
  - Терминалы сабагента живут, пока он открыт (этап 2).

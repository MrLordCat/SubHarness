# Cursor: история чата, сессии и кеш

Cursor работает через официальный `@cursor/sdk` в локальном режиме: вывод идёт
на серверах Cursor, а команды, правки и остальные действия выполняют инструменты
SubHarness-чата. Built-in shell/filesystem/web, внешние MCP-серверы и настройки
проекта в этот мост не загружаются. Профиль, ключ и каталог моделей описаны в
[API_PROVIDERS.md](API_PROVIDERS.md).

## Нативная сессия

Расширение хранит отдельного SDK-агента для сочетания workspace, профиля,
ключа, модели/параметров, рабочей папки и conversation ID. Следующий запрос
продолжает того же агента и передаёт только новые сообщения; возврат после
другого провайдера добавляет его новые ходы и результаты инструментов.
Завершённые собственные вызовы повторно не выполняются.

После reload расширение вызывает `Agent.resume` с ID завершённой сессии и
актуальными callback tools и отправляет только новые сообщения. При отказе
resume сохраняется последний завершённый checkpoint и выводится причина;
автоматическая замена восстановления полным prefill запрещена. Правка или
перемотка ветки, несовместимая с сохранёнными якорями, останавливается до
inference, а завершённая сессия сохраняется.

Незавершённые сообщения остаются в видимом журнале и добавляются после
последнего завершённого checkpoint. Если все native tool calls уже получили
результат, checkpoint неудачного run сохраняется для следующего явного
пользовательского сообщения; при ожидающих результатах он не принимается.
Повтор той же партии результатов возвращает исходную ошибку, в том числе после
reload, без нового SDK run. Обновление каталога инструментов, порядок параметров
и обновления host-context сами по себе native state не сбрасывают; перепакованные
TextParts не меняют канонические пользовательские якоря, поэтому при сохранённом
последнем якоре отправляется только продолжение.

## Холодный перенос и переключение

При первом переходе из Codex, Coco или Claude чат передаёт видимую историю как
есть; перед этим её сокращает self-cleaning чата (`llamacpp.chatContextBudget`,
[CHAT.md](CHAT.md)). Cursor готовит холодный handoff общим планировщиком
[общего контекста](SHARED_CONTEXT.md) в токенах: один SDK run без импортов
с ACK, текущий запрос и текущие изображения сохраняются целиком, полный
оригинал и старые изображения — в архиве, путь к которому виден модели.

`llamacpp.cursorMaxColdHistoryChars` устарел и игнорируется: отдельного лимита
символов больше нет, содержимое определяет общий токенный бюджет.
`llamacpp.cursorMaxHistoryImportParts` также устарел и игнорируется.
Warm/restored сессия отправляет только новые дельты; на каждом SDK-запросе
доступен путь к актуальному JSON-журналу всего видимого чата, поэтому после
нативной компактации модель может перечитать точные детали через инструменты
VS Code. Конечное окно модели и серверная компактация остаются. Chat-only
Cloud fallback не имеет локальных инструментов для архива и явно отклоняет
переполнение контекста вместо молчаливого удаления истории.

## Usage и кеш

Источник — `RunResult.usage` официального `@cursor/sdk`. Нативные результаты
подтверждают: `inputTokens` уже содержит cache read/write, а SDK-helper
`totalTokens` может прибавлять кеш повторно и в расчёте не используется.
Например, input 224 876, read 4 121, write 220 751 означают **4 свежих токена**.
Отсутствующие или некорректные счётчики остаются unreported; при частично
отсутствующей usage сумма помечается estimated. Cumulative usage не
превращается в заполненность контекста.

- `modelSegments: 1` означает один SDK run, а не один вызов модели: внутри
  одного run SDK может выполнить несколько model/tool iterations.
- Cache-write токены означают обработку с записью кеша и включают новый
  материал; это не измерение потерянного старого префикса.
- Нулевой `coldRewriteTokens` в старом JSON — значение по умолчанию при
  отсутствии детализации, то есть «не сообщено», а не «перезаписи не было».
- `toolCatalogHash` и `toolCatalogChanged` сравнивают эффективные SDK
  descriptions и schemas с предыдущим завершённым run; порядок ключей и
  функции callbacks исключены. Изменение каталога инструментов ломает
  префикс кеша, поэтому диагностика показывает его отдельно.

Warm/restored сессия сама по себе не доказывает cache hit: кеш выдаёт сервер,
его TTL и причина низкого hit rate неизвестны. Кеш Codex/Coco в Cursor не
переносится; переносится доступная история. Live Report (Session Quality)
показывает Cursor session mode, свежий вход, cache read, cache creation и долю
чтения кеша, а также причину продолжения или новой сессии; число SDK prompts
не выдаётся за число внутренних backend calls. Quick Access показывает
Tokens/Prompt Cache/Throughput у соответствующего API-профиля.

## Восстановление после Premature close

Ошибка `Premature close` Connect-транспорта SDK не сообщает причину и usage.
На следующем новом сообщении расширение сопоставляет дополнительные SDK
события с готовыми результатами видимой истории по имени, аргументам и
количеству; при совпадении восстанавливается checkpoint, а недостающие
завершённые результаты передаются как история без повторного выполнения.
Отсутствующий результат, противоречащие аргументы, дубли и неразличимые вызовы
блокируют восстановление; служебные записи хранят только call IDs.

## Хранение

Workspace storage содержит `cursor-sdk/` (нативный JSONL store и архивы) и
`chat-history/` (общий видимый журнал, включая изображения). Это локальные
копии содержимого чата, не файлы репозитория; удаление workspace storage
удаляет их. Автоматическая очистка архивов не реализована.

WorkspaceState и `cursor-sdk/completed-sessions.json` содержат только ID, хеши
пользовательских якорей/конфигурации, ссылку на завершённый native checkpoint и
время. Дисковая запись атомарна и завершается до отправки следующего запроса;
при потере workspaceState она восстанавливает привязку. Во время inference
последний завершённый checkpoint остаётся сохранённым с отметкой inflight.
Хранятся не более 32 checkpoints за 7 дней; до 8 idle агентов в памяти, idle
timeout 30 минут. Журнал исходных ошибок хранит до 32 записей по 512 call IDs;
записи старше суток не восстанавливаются. Chat API key остаётся в прежнем
SecretStorage и не записывается в checkpoint.

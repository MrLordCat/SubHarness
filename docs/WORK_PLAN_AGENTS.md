# План работ: производительность, токены, удобство агентов

Три направления по приоритету пользователя (2026-11-26): лёгкость расширения без потери возможностей,
максимум пользы на каждый токен агента, удобство и качество работы агентов с инструментами. У каждого пункта
исходная цифра и ожидаемый выигрыш; после пункта — замер «было → стало» теми же скриптами аудита
(`artifacts/audit/perf/`, `tokens/`, `tools/`; папка в git не входит). Линия 2.1.x, релиз — по просьбе
пользователя.

Правила исполнения: шаги делают субагенты (DeepSeek Flash или Luna — мелкие, Terra — крупные), оркестратор
проверяет каждый дифф; пункт закрывается `npm run compile`, `npm run lint`, полным `npm test`, записью в
CHANGELOG и документацией.

Сделано раньше: этапы 1 (скорость агентов), 1А (лимиты и подписки), 2 (самоочистка контекста) и 3 (надёжность)
вышли в 2.0.9–2.1.0, подробности — в CHANGELOG и в прошлой версии плана
(`git show 1d11dd2:docs/WORK_PLAN_AGENTS.md`).

## Подписка Google: провайдер Antigravity (отложено 2026-11-28, ждёт согласования)

Прототип 2026-11-27 (`artifacts/gemini-spike/`, в git не входит). С 2026-06-18 Gemini CLI для личных аккаунтов
закрыт («This client is no longer supported…»), подписка доступна только через Antigravity CLI. Встраиваемся
через `agy acp`, официальный ACP-сервер для сторонних клиентов. OAuth-токен `agy` напрямую не используем:
это запрещено условиями.

Проверено на прототипе:
- `initialize` занимает 0,2 с после запуска, `session/new` около 1 с, короткий ответ 4–9 с.
- Инструменты чата подключаются через MCP-сервер по HTTP (`127.0.0.1`, токен в `Authorization`), который
  передаётся в `session/new`. Модель их вызывает, результат возвращается.
- Свой текст добавляется к системному промпту через `_meta.antigravity.systemPrompt.append`. Заменить
  промпт `agy` нельзя.
- В результате `session/prompt` есть `usage`: ввод, вывод, чтение кэша, размышления. Кэш работает.
  `usage_update` сообщает окно: 1 048 576 токенов.
- `session/load` в новом процессе продолжает сессию с историей. `session/set_config_option` меняет модель
  внутри сессии.
- Модели: Gemini 4 Hydrogen, Gemini 3.8 Flash, Claude Sonnet 4.6, Claude Opus 4.6, GPT-OSS 120B; уровень
  размышлений от low до xhigh.
- Лимиты отдаёт `agy -p /usage --output-format json`: группы (Gemini; Claude и GPT), окна `weekly` и `5h`,
  `remaining_fraction`, `reset_time`. Недельное окно отсчитывается от первого запроса.
- Каждый вызов MCP-инструмента приходит как `session/request_permission`, только с вариантами allow_once и
  reject_once. Правила из `settings.json` не сработали, отвечает клиент.

Особенности:
- `--app-data-dir` принимает только путь относительно домашней папки, `--gemini-dir` — только абсолютный.
  Поэтому процессу задаются `USERPROFILE` и `HOME`, указывающие на свою папку.
- Токен входа хранится в диспетчере учётных данных Windows (`gemini:antigravity`), а не в папке данных.
- После каждой сессии остаются `conversations/<id>.db` (850 KB после четырёх коротких запросов) и `brain/<id>/`.
- Набор инструментов:
  - у агента по умолчанию есть наши инструменты со схемами и 17 встроенных (`run_command`, `write_file`,
    субагенты, поиск…); первый запрос занимает 14,1 тыс. токенов;
  - у своего агента (`agent.md` с `tools: []` и `mcpServers`) остаются только диспетчер `call_mcp_tool` и
    три служебных инструмента, первый запрос занимает 6,2 тыс. токенов. Но схем наших инструментов модель
    не видит и угадывает аргументы: вызвала `read_file` четыре раза вместо одного. Имена MCP-инструментов
    в `tools` не принимаются ни в одном формате.
- Квота аккаунта: уровень «Antigravity Starter Quota» (`g1-plus-tier`, то есть Free или Google AI Plus),
  только недельные лимиты.
  - Тесты прототипа (около 170 тыс. токенов вместе с кэшем) израсходовали 24% недельного лимита Gemini.
  - Один запрос к Claude Sonnet 4.6 на 11,7 тыс. токенов израсходовал 2,2% лимита группы Claude и GPT.
  - На Google AI Pro лимит больше и обновляется каждые 5 часов; это по документации, не проверено.

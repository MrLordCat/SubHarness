# План работ: производительность, токены, удобство агентов

Три направления по приоритету пользователя (2026-11-26): лёгкость расширения без потери возможностей,
максимум пользы на каждый токен агента, удобство и качество работы агентов с инструментами. У каждого пункта
исходная цифра и ожидаемый выигрыш; после пункта — замер «было → стало» теми же скриптами аудита
(`artifacts/audit/perf/`, `tokens/`, `tools/`; папка в git не входит). Линия 2.1.x, релиз — по просьбе
пользователя.

Правила исполнения: шаги делают субагенты (DeepSeek Flash или Luna — мелкие, Terra — крупные), оркестратор
проверяет каждый дифф; пункт закрывается `npm run compile`, `npm run lint`, полным `npm test`, записью в
CHANGELOG и документацией.

Сделано раньше: этапы 1 (скорость агентов), 1А (лимиты и подписки), 2 (самоочистка контекста) и 3 (надёжность)
вышли в 2.0.9–2.1.0, подробности — в CHANGELOG и в прошлой версии плана
(`git show 1d11dd2:docs/WORK_PLAN_AGENTS.md`).

## Направление 2. Эффективность токенов

- [ ] **Э1 Длинные результаты не режутся посередине (дефект моста; отчёты — 2.1.1, пагинация — 2.1.3).** Claude режет любой результат до 16 000
  символов, оставляя начало и конец (`app-server-client.ts:24`), Codex — до 12 000, HTTP — до 24 000. При этом
  `read_file` отдаёт до 200 000 символов, а терминал — до 30 000. На аудите отчёты трёх субагентов (≈55k
  символов) пришли оркестратору без середины. Нужно:
  - [x] отчёты субагентов не резать (сделано в 2.1.1: `subagent` и `wait_subagents` получают до 60 000
    символов у Claude, Codex и HTTP — `src/tools/tool-result-limits.ts`; длиннее — по-прежнему начало и конец);
  - инструменты отдают объём под лимит провайдера, с явным продолжением («строки 1–400 из 2 300,
    продолжить: `startLine: 401`»).

  Выигрыш: оркестратор видит отчёты целиком, меньше повторных чтений (40% чтений в ходе). Риск низкий, объём M.
- [x] **Э2 Старые картинки устаревают** (сделано в 2.1.1: картинка весит 8 192 символа, `IMAGE_RESULT_CHARS`;
  результат `view_image` устаревает через запрос, результат с картинкой другого инструмента — как большой). Очистка учитывает только длину текста результата
  (`context-cleaning.ts:139`), поэтому `view_image` и скриншоты не заменяются никогда. Учитывать вес картинки
  (≈4k токенов), старые заменять пометкой с путём. Выигрыш до ≈20k токенов на запрос (≈10% медианы). Риск
  низкий, объём S.
- [ ] **Э3 Старые аргументы правок.** Аргументы вызовов — 33% живого окна, очистка их не трогает. Аргументы
  `create_file`, `replace_string_in_file`, `multi_replace_string_in_file` и задания завершённых субагентов
  из прошлых запросов заменять пометкой («X: +N −M строк»). Выигрыш ≈10k токенов на запрос. Риск средний,
  объём M.
- [ ] **Э4 Очистка истории субагента.** Субагент только укорачивает историю у края (`subagent-runner.ts:85-99`);
  у DeepSeek медиана 89k на раунд, был отказ «context nearly full». Применить к нему правила устаревания.
  Выигрыш 8–18k токенов на раунд. Риск средний, объём M.
- [x] **Э5 Бюджет очистки учитывает схемы инструментов** (сделано в 2.1.1, `requestFixedTokens`). Сейчас считается только системный промпт
  (`chat-controller.ts:2406`, `:2515`), каталог (3–7k токенов) не входит. Корректность, риск низкий, объём S.
- [x] **Э6 Старые копии индекса памяти** (сделано в 2.1.1: очистка убирает индекс из всех сообщений, кроме
  новейшего; тексты записей остаются, `staleMemoryIndex` в части сжатия). В сессии 27 блоков памяти (64 тыс. символов), в живом окне 3. При
  очистке оставлять последний. Выигрыш ≈1k токенов на запрос. Риск низкий, объём S.
- [ ] **Э7 Повторы инструкций.** Гайд по субагентам в промпте (2,3 тыс. символов) повторяет описание `subagent`,
  то же с памятью. Выигрыш ≈300 токенов на запрос. Риск низкий, объём S.
- [ ] **Э8 Разбивка запроса в Session Quality.** Системная часть, схемы, история: результаты, аргументы, сводка,
  картинки, память. Без неё не измерить Э2–Э7 и не настроить Э9. Объём S/M.
- [ ] **Э9 Настройка порогов (после Э8, по замерам).** Возраст больших результатов (сейчас 2 запроса и 8 000
  символов) и размер сводки (35 тыс. символов, 17% окна): до ≈12k и ≈4k токенов на запрос. Каждая очистка
  стоит ≈120k записи в кэш, поэтому цель — реже и глубже. Риск средний/высокий, объём S.
- [ ] **Э10 Проверить цикл сводок DeepSeek.** В логе 2.0.8 — 18 сводок (521k токенов) с одинаковым входом три
  раза за 3 минуты; в логах 2.0.13 такого нет. Проверить на 2.1.x.
